# Support SQL Toolkit — разбор тикетов поддержки через SQL

> Портфолио для роли **специалиста технической поддержки L1/L2**: как по жалобе клиента найти причину в базе данных, ответить клиенту и правильно эскалировать задачу в разработку.

[![CI](https://github.com/nikitaamoev31-sudo/ai-portfolio/actions/workflows/ci.yml/badge.svg)](https://github.com/nikitaamoev31-sudo/ai-portfolio/actions/workflows/ci.yml)

## Задача
Учебная база SaaS-сервиса онлайн-записи (салоны, клиники, студии): клиенты, тарифы, оплаты, сотрудники, тикеты, логи входов и API. В данные заложены типичные инциденты, с которыми приходят в поддержку: двойное списание, «оплатил, а доступ закрыт», блокировка аккаунта, массовые ошибки 500, лимиты тарифа. Цель — найти каждый из них одним SQL-запросом и закрыть тикет.

## Что сделано
- **8 SQL-запросов** под реальные ситуации поддержки — каждый начинается с комментария «какой тикет решает» ([queries/](queries))
- **5 разборов тикетов** в формате «жалоба → расследование → ответ клиенту → эскалация в Jira» ([cases/](cases))
- Отчёты для руководителя: нарушения SLA, KPI сотрудников (медиана первого ответа, % SLA, CSAT), очередь на смену
- Схема PostgreSQL на 10 таблиц с внешними ключами, CHECK-ограничениями и индексами ([db/schema.sql](db/schema.sql))
- Детерминированный генератор данных: фон + заложенные инциденты ([db/gen_seed.py](db/gen_seed.py))
- **8 автотестов** (pytest): каждый проверяет, что запрос находит именно заложенный инцидент, без ложных срабатываний

## Стек
PostgreSQL 16 · SQL (JOIN, LATERAL, CTE, FILTER, date_trunc, PERCENTILE_CONT) · Python · pytest · Docker Compose · GitHub Actions

## Запуск
```bash
docker compose up -d --wait
docker compose exec db psql -U postgres -d helpdesk -f /queries/01_double_charges.sql
```
Подставьте любой файл из `queries/`. Подключение из DBeaver/DataGrip: `localhost:5432`, база `helpdesk`, пользователь `postgres`, пароль `postgres`.

## Тесты
```bash
pip install -r requirements.txt
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/helpdesk pytest
```
Тесты пересоздают схему из `db/` и проверяют конкретные значения: id клиентов, номера транзакций, количество попыток входа. Запускаются в CI на каждый push.
